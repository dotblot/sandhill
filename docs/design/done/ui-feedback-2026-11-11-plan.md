## 3. Console 的图不再自动送到 Plots

现在：Console 里每次运行产生的图都会自动加入 Plots 面板，并切到 Plots 标签。

做法：
- Console 里照常在输出下面显示图。默认不再送到 Plots，也不再自动切换标签。
- 鼠标停在 Console 的图上时，右上角出现 “Send to Plots”（发送到 Plots）按钮，与笔记本图的 Save/Copy 按钮放在一起。
- Console 标签栏的按钮区加一个 “Send all plots to Plots”：把当前 Console 会话里还没送过去的图按顺序全部送过去。
- Plots 面板的菜单里加一个开关 “Send Console plots automatically”（自动发送 Console 的图），默认关闭。打开后就是现在的行为。这个开关和已有的 “笔记本的图是否进 Plots” 开关放在一起，按设备分别记住。
- 送过的图要记住：重新连接或重启 App 后，Plots 里只恢复送过的图，不会把 Console 的所有旧图又塞回去。记录放在本机设置里，按设备、会话和图的编号保存。

## 8. AI 面板的命令行模式改用原生界面

现在：Claude Code 和 Posit Assistant 在命令行模式下运行的就是它们自己的程序，可以直接打字。Codex 和 Antigravity 的聊天是 Sandhill 通过它们的“后台接口”驱动的。命令行模式里显示的只是这个转接程序，不是 Codex/agy 自己的界面，所以打字没有反应。

做法（推荐）：
- 切到命令行模式时，Sandhill 先让转接程序暂停，然后在同一个终端里启动原生程序，并接着同一段对话：
  - Codex：`codex resume <对话编号>`
  - Antigravity：`agy --conversation <对话编号>`
  - 模型、权限模式和 Sandhill 的 MCP 工具都照聊天模式的设置传进去。
- 切回聊天模式时，先正常退出原生程序，再让转接程序重新读入这段对话。在原生界面里发生的问答会补进聊天记录。
- 同一段对话任何时候只让一个程序在写，避免两边同时写坏对话记录。
- Claude Code 和 Posit Assistant 不变。

另一种做法：去掉 Codex/Antigravity 的聊天模式，只用原生界面，聊天记录从它们的记录文件里读。这样更简单，但聊天面板里的按步骤显示、提问和批准都会变差，所以不推荐。

需要注意：两个程序轮流接管同一段对话，依赖 Codex 和 agy 的“按编号续接”功能。我已确认本机的 codex 0.167.0 和 agy 1.5.5 都有这个功能。

## 9. Quarto（.qmd / .Rmd）里加代码块和文字块的按钮

现在：.qmd/.Rmd 用和 .ipynb 一样的笔记本视图显示，但添加按钮只对 .ipynb 打开。

做法：
- 和 .ipynb 一样，在块之间和文末显示 “+ Code” 和 “+ Markdown” 按钮，快捷键 a / b 也一样。
- 新代码块写成 ```` ```{r} ```` 或 ```` ```{python} ````，语言取这个文档当前内核的语言；还没选内核时，取文档里第一个代码块的语言。
- 新文字块就是一段普通文字，前后各空一行。
- 文件里原有的文字、空行和块选项一个字不改，只在插入的位置加内容。保存时仍按原文件格式写回。
- 这次只做“添加”。删除、移动块以后另议。

## 5. 终端打开时输入区出现乱码

查到的事实：
- 这些乱码是终端对“查询”的自动回答，比如问终端版本、背景色、光标位置等。提问的是之前在这个终端里运行过的 agy 和 fish。
- 这些回答在之后某次打开终端时被一次性重新发给了 zsh，于是出现在输入行里。乱码里还带了一个回车，zsh 把它当命令执行了一次（“command not found”，没有造成破坏）。
- 我用你服务器上这个终端的原始记录（约 2.2 MB）做了四种复现：本机、旧版终端宿主、模拟的慢速远程连接，以及真实的 ssh 到 Ubuntu（用临时的独立目录，没碰你正在用的后台程序）。四种情况下重新打开终端都不会出现乱码。所以触发条件还没找到，不是简单的“打开就发”。

做法（建议两步一起做）：
1. 在后台程序里加一道保护：发往终端的输入如果全部是终端的自动回答，而这个终端最近 10 秒内没有发出过任何查询，就丢掉。这样不管是哪条路径产生的迟到回答，都不会再进到 shell。普通按键不会被拦。唯一可能误拦的是极少见的带修饰键的 F3（Shift+F3 的编码和“光标位置回答”相同），而且只在 10 秒内没有任何查询时才会。
2. 被丢掉时写一条日志，记下终端、时间和来源连接。下次再出现时就能直接定位真正的原因，再修根源。
