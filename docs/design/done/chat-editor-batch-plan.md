## 1. Earlier prompts and right-click in the conversation

"Up/down arrow to choose a previous prompt … select the history prompt and
right click to copy or send the selected text to the composer. The AI
output can be selected, but right clicking shows nothing."

Today: no prompt recall; the user's own messages can't be selected; replies
can be selected but have no right-click menu.

- **Up** in the message box, with the caret on the first line, puts the
  previous prompt in the box; Up again goes further back, **Down** comes
  forward, and past the newest the unsent text comes back as it was.
  Which prompts: **Ask** (this conversation's, or every conversation's in
  the project, newest first).
- The user's messages become selectable, like replies.
- Right-clicking selected text in the conversation (a message or a reply)
  opens a menu: **Copy**, **Send to Message Box** (the text goes into the
  box at the caret, for editing before sending). Without a selection the
  menu offers Copy Message for the message under the pointer.
- Code: `agents/composer_view.rs` (Up/Down beside the @ list's keys),
  `agents/view/chat_rows.rs` (selectable message, menu), the window's text
  selection (`TextSelection::selected_text`).

## 2. AI code: into the file, and buttons on every code block

"When choosing File, the code generated by AI is not added to the file …
copy, insert at the cursor or add to a new cell below current cell in an
open document, run in console, or insert into a new file. Syntax
highlighting in the code part."

Why it goes to the Console today: with "Code File", `add_cell` writes only
into a document the message names with @ (or a pinned one); with none
named, it runs the code in the Console. That follows the decision of
2026-11-12 that messages carry no document of their own. Agents also use
`run_code` for small checks, which always runs in the Console.

- **Ask**: with "Code File" and no @ file, the code goes into the document
  in front (the active editor tab: a new cell below the current one, or
  the end of a script). This changes the 2026-11-12 decision for this one
  case. With no document open, it runs in the Console as today.
- The agents' instructions say plainly: with "Code File", everything the
  user asked for goes in with `add_cell`; `run_code` only for checks.
- Every code block, in replies and in the steps' cards (the code an agent
  ran), gets a row of small buttons on hover: **Copy**, **Insert at
  Cursor** (the active document), **Add Cell Below** (below the current
  cell of the active notebook or Quarto/R Markdown document), **Run in
  Console**, **New File** (an untitled file of the code's language, opened
  in the editor). Buttons that can't act (no open document) are dimmed
  with a tooltip saying why.
- The steps' code is coloured like the editor's and can be selected;
  their output can be selected too.
- Code: `crates/daemon/src/mcp/documents.rs` (`add_cell` target),
  `crates/daemon/src/agents.rs` (instructions),
  `agents/view/chat_rows.rs` (`code_block_actions`), `agents/view.rs`
  (`step_card`), `workbench/tabs.rs` (`insert_into_active_document`),
  `editor/cells.rs` (`add_cell_with`), `workbench/runs.rs`.

## 3. Tables in replies

"Copy, download or show the table in the data explorer."

Under each table in a reply: **Copy** (tab-separated, so it pastes into
Excel as cells), **Save as CSV…** (a save dialog) and **Open in Data
Explorer**. The data explorer only shows tables that live in an R or
Python session, so the third button needs one:
- **Ask**: (A) put it into the Console's session as a data frame
  `ai_table_1` (numbers as numbers), which then shows in Variables and in
  the explorer, live like any other; or (B) save a CSV under
  `.sandhill/tables/` and open it in Sandhill's CSV view instead (no
  session touched, but not the data explorer).
- Code: `TextView::table_actions` (gives the cells), `panes/explorer.rs`
  (open by name), the save dialog in `panes/explorer/export.rs`.

## 4. Suggestions after a turn

"One or two suggestions of what to do after finishing a turn."

When a reply finishes, one or two short chips show under it ("Plot the
top 20 genes", "Save the table as CSV"). Clicking one puts its text in the
message box (not sent), as "Start with" does. They go away when the user
sends the next message. **Ask** where they come from:
- (A) The agent writes them: its instructions ask it to end each reply
  with a hidden line of one or two next steps, which Sandhill takes out
  and shows as chips. Specific to the work, costs nothing extra; an agent
  that forgets them shows none.
- (B) Sandhill picks them from what happened (a plot was made → "Save this
  plot"; an error → "Fix the error"). Always there, instant, but generic.
- (C) A second short request to the agent after each turn. Specific, but
  uses quota and takes seconds.

## 5. The device popup

"Redesign the device details pop-up … a switch to show/hide the resource
usage on the status bar. Default to show."

Today the popup is a list of rows (address, sandhilld version, running
time, kernels, app version) and buttons; resources have their own small
popups from the status bar numbers. The new popup, 340px wide, in the
style of the quota and context panels:

```
┌─────────────────────────────────────────┐
│ ▣ Huan's MacBook Pro        ● Connected │
│   sandhilld 0.1.0 · up 2h 14m           │
├─────────────────────────────────────────┤
│ ◔ CPU 12%   ◑ Memory 41%                │
│ ◔ GPU 3%    ◕ Disk 72%                  │
│   6.6 of 16 GB memory · 3 kernels       │
├─────────────────────────────────────────┤
│ KERNELS                                 │
│ R 4.6.2 · Ark          analysis.qmd     │
│ Python 3.12 (omicverse)  qc.ipynb       │
├─────────────────────────────────────────┤
│ Show usage in status bar         [ on ] │
├─────────────────────────────────────────┤
│ [Restart sandhilld]  Manage…   Log      │
└─────────────────────────────────────────┘
```

- Header: device, name, a status dot with the state, then sandhilld's
  version and how long it has run (and, for another computer, its address
  and how it's reached).
- Usage: four rings (only those the device has), with the memory figure
  and the kernel count under them; each ring opens its details as today.
- Kernels: the running sessions, one line each (name, the files using it).
- The switch: on by default; off hides the usage numbers in the status
  bar and stops measuring them (the same setting as today's chevron).
  **Ask**: keep the chevron as well, or the switch replaces it.
- Actions as today (Restart, Connect, Reconnect/Disconnect by state),
  Manage resources and storage…, Open log.
- Code: `connection.rs` (popup), `panes/machine.rs` (rings, details),
  `prefs::resources_shown`.

## 6. Agents page order

"Agents enabled are on the top of the list."

Welcome → Agents lists the turned-on agents first, then the turned-off
ones, each group by name. The order is fixed when the page opens, so a box
doesn't jump away under the pointer when its switch is clicked; it moves
the next time the page is shown. Code: `agents/accounts.rs`.

## 7. Ask AI about a cell or a selection

"A button on the cell toolbar to ask AI about the chunk/cell … right
clicking selected code, ask AI about the selected code."

- The cell toolbar gets an **Ask AI** button (the agent mark). It opens the
  AI pane, adds the cell as a # chip (which brings its code and its latest
  output) and puts the caret in the message box, for the user to type the
  question.
- The editor's right-click menu gets **Ask AI About Selection** (dimmed
  without a selection): the selected code goes as a chip named
  `analysis.R:12–18`, the same way.
- Nothing is sent by itself. Code: `editor/cell_view.rs` (`cell_tools`),
  `agents/cell_ai.rs`, `agents/input_box.rs` (`attach_text`), the editor's
  menu (`context_menu`, keeping its present items).

## 8. The explanation box

"The explanation box comes up even when the pointer is in the blank area …
of a list or vector over several rows. A 3 s delay."

Why: past the end of a line, the pointer counts as the line's end, and the
language server answers there with the whole list, so the box appears and
stays over all its rows. Fix: the box shows only while the pointer is over
a name's own letters, and its area is that name, not the whole list. It
appears after the pointer rests 3 seconds (today 0.15 s); moving off the
name closes it at once.
Code: `editor/language/providers.rs` (`hover`), the editor's mouse move.

## 9. Code in the Console

"The code in the console is not selectable."

The code shown for each run in the Console can be selected and copied
(⌘C, and right-click Copy), keeping its colours, like the output below it
already can. Code: `view/console_pane.rs`, `editor/output_text.rs`.

## 10. Variables first in suggestions

"The variables always come first in the autosuggestion when they're present
in the variables pane or the file."

Names in the session's Variables pane and names assigned in the file
(`x <- …`, `x = …`, `def x`, `import … as x`, loop variables) come first
in the completion list whenever they match what was typed, before
functions, arguments and packages; among themselves, the better match
first. Code: `editor/language/providers/completion_items.rs` (`rank`,
with a test), `providers.rs` (gathering the names).
